## 环境坑：GitHub 大包传输极慢

- 本机到 github.com 的小请求正常（`git ls-remote` 秒回），但**大包传输约 20KB/s**；`raw.githubusercontent.com` code=000 直接失败，`codeload.github.com` 挂死；同机 npm registry 有 ~200KB/s（说明是 GitHub 侧慢，不是本机网络）。
- 后果：`git fetch upstream master`（落后 1167 提交）跑 500s 仍只下到 9MB，被 timeout 杀掉后报 **`fatal: fetch-pack: invalid index-pack output`** —— 这个报错其实是"下载被中断"的假象，不是 index-pack 本身坏了。
- 对策：需要抓上游时，用 `run_in_background=true` 起 fetch 并给足时间（不要 `timeout`）；先 `-c http.version=HTTP/1.1`。
- `&` 起的后台 git 会随 Bash 工具调用结束被杀，必须用 `run_in_background=true`。
