## 环境坑：GitHub 大包传输极慢

- 本机到 github.com 的小请求正常（`git ls-remote` 秒回），但**大包传输约 20KB/s**；`raw.githubusercontent.com` code=000 直接失败，`codeload.github.com` 挂死；同机 npm registry 有 ~200KB/s（说明是 GitHub 侧慢，不是本机网络）。
- 后果：`git fetch upstream master`（落后 1167 提交）跑 500s 仍只下到 9MB，被 timeout 杀掉后报 **`fatal: fetch-pack: invalid index-pack output`** —— 这个报错其实是"下载被中断"的假象，不是 index-pack 本身坏了。
- 对策：需要抓上游时，用 `run_in_background=true` 起 fetch 并给足时间（不要 `timeout`）；先 `-c http.version=HTTP/1.1`。
- `&` 起的后台 git 会随 Bash 工具调用结束被杀，必须用 `run_in_background=true`。

## 启动失败修复：client bundle 缺失

- 现象：`dsh --profile web` 启动即崩，`ClientPackageCompositionError: 6 client packages failed to compose: client bundles not found; run pnpm run build`。
- 根因：全仓库 **0 个 `lib/client.js`** —— 之前只跑过 `tsc -b`（生成了 `lib/types` 与 tsbuildinfo），**tsdown 打包阶段从未跑过**。
- 修复：跑 `pnpm run build`（= `tsx scripts/build.ts`），51 秒完成，产出 58 个 client.js、234 个 client artifact。
- 经验：**同步/合并大范围变更后，typecheck 通过 ≠ 可启动**，必须补跑 `pnpm run build`。判断依据：`find packages apps -path '*/lib/client.js' | wc -l` 是否为 0。
- 启动命令（本机）：`PATH="/d/work/space/.dsh-bin:$PATH" NODE_OPTIONS= CODEBUDDY_SAFE_DELETE_BULK_GUARD= pnpm dsh --profile web` → `http://127.0.0.1:3080/?token=<token>`。
- 残留无害警告：`bsk probe failed (spawn bsk ENOENT)` —— 外部插件 `@wxg-prc-cpg/browser-skill-dsh-plugin` 需要 `bsk` CLI，未安装时浏览器工具降级为安装提示，不影响启动。（`modlens vision ... cannot get required service "llm" in inactive context` 在构建修复后已消失。）
