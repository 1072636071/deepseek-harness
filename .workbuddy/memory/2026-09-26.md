## 合并 dsh-v0.1.7-rc.2 与启动修复（本机环境约束大爆发）

### 根因：本机进程无 reparse point 遍历权限（决定性发现）

- 现象：`node_modules` 里任何 pnpm 符号链接/junction，**目录列表能过、读文件必失败**。node 侧 `fs.existsSync(link/x)` = false、`readdir` 报 `UNKNOWN`；PowerShell 直读报中文错误「**无法遍历该路径，因为它包含不受信任的装入点**」（= STATUS_UNTRUSTED_MOUNT_POINT）。
- 已排除：`dangerouslyDisableSandbox` 无效、`NODE_OPTIONS` shim 无关（MSYS `head`、PowerShell 同样失败）、C: 盘同样复现（非 D: 盘特例）；自建 junction/相对 symlink/绝对 symlink 全部不可穿越。
- 后果：**pnpm isolated 布局在本机不可用**；`pnpm install --config.node-linker=hoisted` 也跑不完（pnpm 会读自己建的 workspace 链接 → 同一错误 → `ERR` 中断，见 `native/system/packages/entry/...`、`website/node_modules/cytoscape` 两次实测）。
- 另一个坑：`fs.cpSync` 在**源目录含符号链接**时会让进程被直接杀掉（exit 127/134、无输出）；逐项自研拷贝则正常。`fs.linkSync`（硬链接，非 reparse point）可用 → 实体化请用硬链接。

### 客户端 "Failed to load plugins" 根因链（用户报的 require 越模块表问题）

- 现象：`failed to import loader entry (@deepseek-ai/dsh-api-remotes): require("@deepseek-ai/dsh-agent-preset-registry/remote") missed the module table`。
- 三个真因，逐个排掉：
  1. **profile 里 19 个 `@deepseek-ai/*` 是旧版**（0.1.2-rc.1，由第三方插件带进来的传递依赖）。typert loader 按 config 树（= profile）解析包，其中 dsh-llm / dsh-commands 命中 profile 的旧副本 → manifest 里没有 `create()` 工厂 → `typert-loader` 校验失败 → 远程模块表不完整。修：`.workbuddy/refresh-profile-core.cjs` 用仓库当前 rc.2 实现覆盖这 18 个包（588 文件）。验证：`dsh` 启动不再有 codec 报错。
  2. **我加的深层别名块把 `<pkg>/remote` 指到了 `.d.ts`**（生成器原先偏好 `types` 条件）。tsdown/rolldown 也吃 tsconfig paths → 把 `.d.ts` 当模块 → `[MISSING_EXPORT] "default" is not exported by .../typert.remote-client.d.ts` → client 面那个分块整块失败 → `/remote` 客户端贡献没进模块表。修：别名生成器按子路径区分——`./remote` 取运行时目标（default→import→types），其余仍取 `types`（TS 才找得到声明；全改运行时会让 12 处 TS7016 复现）。验证：client 面 8 块全绿，`grep 'require(".../remote")'` 在 `api-remotes/lib/client.js` 与下发 bundle 里均为 0（已内联），模块表 11.1MB / 61 模块。
  3. **分块脚本漏掉整组 `packages/client/*`**（判定写了 `AGENTS.md` 而不是"含 package.json 的子目录"）→ client 包的 **host 面产物**（`lib/index.js`）从未重建 → `shortcuts (@deepseek-ai/dsh-client-shortcuts): failed to import`。修：重跑 host 面后 `lib/index.js`/`protocol.js` 生成，告警从 2 条降到 1 条。
