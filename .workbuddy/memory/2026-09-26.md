### 内测声明「点确认报暂时无法保存确认状态」→ 根因：app-boot 双模块副本（已修）

- 现象：设置页的内测声明（welcome notice）点「继续」报 `暂时无法保存确认状态，请重试`。实测**所有** profile 写入都挂：`settings/mutate`/`settings/update` 任何命名空间都返回 `settings/rejected: dsh: profile reload requires the root Include entry`。欢迎弹窗只是最先撞上的那个。
- 定位手法（可复用）：用启动时打印的 `?token=` 换 cookie（`GET /?token=…` → 303 + `set-cookie`），再以 `POST /api/<method>` 发 `{"type":"client-request","rpcId":…,"method":"settings/describe","payload":{"args":{}}}`（args 必须是**对象**，不是数组）。`settings/describe` 能列出全部命名空间说明 describe 面正常，`settings/mutate` 的 500 级 message 直接给出了真因。
- 真因：`mountRootInclude` 把根 Include 记在**模块级 WeakMap** `bootstrapIncludes` 里。本机一份安装里 app-boot 有两个副本——启动器（`apps/cli`，tsx 走 tsconfig paths）加载 `src/index.ts` 半边并登记，而 `lib/` 加载的插件（config-editor / hmr / plugin-manager）加载 `lib/index.js` 半边去读 → 两个 WeakMap 各自为空 → `reconcileProfilePatches` 找不到根 Include。
- 验证证据：在 `lib/index.js` 的抛出点加诊断后，日志出现 `no root include {isRoot:true, name:'root', hasRootEntry:false}` 共 8 次，而**本副本内 `mountRootInclude` 从未被调用**（无对应日志）——双副本实锤。
- 修法（已提交 `c647ee4838`）：`packages/boot/app-boot/src/index.ts` 用 `export const BOOTSTRAP_INCLUDE = Symbol.for('@deepseek-ai/dsh-app-boot/bootstrap-include')` 把根 Include 挂在 booted context 上（`Reflect.get/set`；cordis Proxy 对 symbol 键直接透传），三处引用改为 `bootstrapIncludeOf(ctx)`；补测试钉住「第二份副本也能从 context 读到同一个 entry」。
