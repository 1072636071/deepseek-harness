常见疑问 FAQ

为什么我看到的“系统提示词”每次都不一样？
因为其中夹杂了随 step 变化的动态上下文快照（沙箱/审批/子代理任务）与随文件触达变化的 AGENTS.md 指令。真正稳定的 system 段（身份/人格/工具指引）若无人改动，渲染应保持一致——你若看到它变了，多半是插件加载顺序、变量值或作用域遮蔽在起作用。
插件要“对模型说句话”，一定得动 system-prompt 吗？
不一定。三种途径各取所需：a) 一段长期适用的指引 → systemPrompt.section()；b) 一个会随状态变化的“事实” → systemPrompt.context()（进 runtime 快照）；c) 工具 → 提供 ToolRuntime 让其自动注册 schema。只有需要“完全换一套人格”时才用 complete 段。
为什么“一段 prompt 算两遍”（assemble 求值 + render 插值）？
两阶段让装配与渲染分离：assemble() 产出“已求值但未插值”的段 + 变量值表 + 有序 schema，供拦截瀑布与工具统一处理；renderPrompt() 才做 {{var}} 插值、去空段、空行连接。这样“谁在什么上下文算的值”可追溯，也让一次请求不必把所有 context 重复插值两次。
同名段在作用域层“遮蔽”了，会不会反而丢了我想要的内容？
遮蔽是刻意的“就近优先”。子代理、preset 想让你这层的人格/规则生效，就得盖掉全局；若你希望全局规则也保留，应改用不同 name 的段（不同名会并存，都进 system）。同一层里同 name 重复注册则会直接抛错，防止手滑。
我在哪能实际“看见”这些注入？
观察请求体/会话事件最直观：session/event 里的 user/message（source 标注 agent-instructions、plugin: @deepseek-ai/dsh-system-prompt）就是被注入的 user 角色内容；system 与 tools 在发往 LLM 的请求 payload 里可见。跟踪 system-prompt/assemble 事件可拦截审查。
想看实例？本仓库根目录就有 AGENTS.md / CODEBUDDY.md——当你让 DSH 读取项目文件时，观察它如何把其中的“文件级指令”作为 <system-reminder> 折进上下文，就是第 04 章阶段 4 的现场。
全书完。一句话回顾：DSH 没有“一条”系统提示词，只有“一套装配规则”——注册（第 01 章）→ 四种原料（02）→ 作用域（03）→ 五阶段注入（04）→ 请求解剖（05）→ 去重快照（06）→ 一切为了缓存（07）。想精简有旋钮（08），想抠字有原文（09），想换玩法有模式（10）。
