注入全景：从「启动」到「每一步」的五个阶段

把“提示词到底在哪些时候被注入”拆成五个阶段。你会发现：真正“越到后面越热闹”的是阶段 3/4/5——它们都发生在运行中、而且是“再注入/重快照”。这正是你在请求体里看到许多提示词片段的原因。

各阶段注入的真实文本原文，见第 09 章原文库。
阶段 0启动 / 配置
装配规则被登记。 harness 身份、部署人格、各插件的段与变量、全局 toolOrder 在进程启动时注册进 registry；Cordis 按配置文件把第一方 + 第三方插件挂载上树。 ← 静态层的来源
▼
阶段 1会话 / agent preset
作用域层建立。 每次开 agent（含子代理）时，preset/persona 等往 agent.ctx 作用域登记同名段，遮蔽全局。同一份二进制可跑出不同人格的 agent。 ← 第 03 章的机制在这里发生
▼
阶段 2每个 step · assemble
拼 system 正文与工具集。 轮次内每个 step 前调用 assemble()：段按序拼接、变量现算、schema 收集排序，产出 system 文本。 ← 提示词段“稳态”在这里
▼
阶段 3每个 step · 运行时注入
动态上下文“重快照”。 把 sandbox/approval 等可变事实打包成一条 user 消息“Current runtime context…”，追加进消息历史。 ← “运行还会注入”的本体，第 06 章专讲
▼
阶段 4 / 5文件指令 & 子代理
随运行涌入。 AGENTS.md/CLAUDE.md 基线进入 durable 上下文；当 agent read/write/edit 触碰某文件后，新的嵌套指令经 agent/pre-step 折进 inbox；子代理另建独立 scope。 ← 提示词“增长”的来源

阶段 4 值得单独看一眼：workspace 指令的“活更新”

会话开始前

基线指令先入队

项目根与 $DSH_HOME 下的 AGENTS.md / CLAUDE.md（含 .local 覆盖层）被加载渲染，作为带 agent-instructions 来源标记的 user 消息进入 durable 上下文——在第一次模型请求之前。

运行中 · 每次文件触达

read/write/edit 触发增量投影

工具结果管道监听 tools/result：一旦触碰了含嵌套指令的路径（如子目录的 AGENTS.md），或已加载文件内容变化/被删除，就重新协调并生成“Additional instructions / Updated instructions / Instructions removed”增量消息。

下一个 pre-step

折进消息流，位置讲究

经 agent/pre-step 瀑布折入，刻意排在直接 prompt 之后、driver 注入的 runtime 快照之前——直接的话优先，事实快照殿后。

直观感受：你常疑惑“我明明只发了一句 followup，为什么模型面前塞了那么多说明？”——因为这些不是“你发的话”，而是 DSH 在阶段 2~5 给每个 step 现拼的引导 + 现刷的运行时事实 + 现读的项目规则。模型看到的从来不是“你的一句话”，而是“一条被喂饱的上下文”。
本章心法：五个阶段 = 注册（0）→ 分层（1）→ 拼装（2）→ 快照（3）→ 涌入（4/5）。前两个是“规则建立”，后三个是“每步执行”。下一章把一次真实请求摊开看排布。
