作用域分层：全局一套，agent / 子代理各自遮蔽

提示词是带作用域(scope)的：插件通过 agent.ctx（某个具体 agent 的上下文）注册，就只影响那个 agent，并可遮蔽同名全局项。这解释了“为什么不同 agent / 不同子任务，看到的人格和工具指引不一样”。

本章对应源码：packages/core/system-prompt · packages/preset/persona · packages/subagent
遮蔽 ≠ 并列。同名段/变量/上下文，作用域层会盖掉全局层，而不是同时出现两条。你常看到的“梁神模式”“某 preset 人格”，本质就是在一个 agent 作用域里用同名的 deployment:persona 段，把部署全局人格替换掉——正因为两边都叫同一个名字，替换才成立而不是重复。
全局层 global

注册在无作用域的 ctx：harness 身份、部署人格、工具段等默认对所有 agent 生效。范围最大、优先级最低。

agent 作用域

通过 agent.ctx 注册：一个人格 preset、一份工具指引只作用于此 agent，并遮蔽全局同名项。装配时“离得越近的层”优先。

子代理作用域 child

主代理派生子代理时，会给 child 一个独立 scope：注入 delegation 上下文与子代理专属 persona。各子任务互不污染。

现场代码：子代理如何换人格

// packages/subagent/subagent/src/child-agent.ts
childCtx.systemPrompt.context({
  name: 'subagent:delegation', order: 120,
  text: SUBAGENT_DELEGATION_CONTEXT });
childCtx.systemPrompt.section({
  name: 'deployment:persona', order: PERSONA_ORDER,
  text: composition.persona });  // 同名段 → 遮蔽全局人格

而 packages/preset/persona 是一个纯作用域行：它不能全局挂载（会和注册表自己的 persona 登记撞名报错），只能放进 agent preset——这个“限制”正是它的存在理由：agent 预设如果不能改人格，就只能改工具、改不了身份。

遮蔽的边界与安全网

同层重复注册同一层里 name 重复直接抛错，错误信息还会提示“要按 agent 覆盖请走 agent.ctx”——防止手滑。
瀑布按作用域筛system-prompt/assemble 监听者只收到自己作用域的装配；但 system-prompt/change 注册表变更通知刻意不筛——全局变更影响每个作用域，人人需要知道。
警告遮蔽是刻意的“就近优先”。想让全局规则也保留，就用不同 name 的段（不同名会并存）；同名的效果永远是“二选一”。
本章心法：作用域分层让“一份二进制跑出千种 agent”成为可能——人格 preset、子代理委托、团队角色，全都只是不同作用域里的一批同名/异名段。
