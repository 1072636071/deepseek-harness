实测：DSH 自带提示词到底啰不啰嗦？

直觉上“注入很多阶段 = 提示词很臃肿”。我们把第一方段落逐个翻出来量了量，结论相反——DSH 是刻意“反啰嗦”设计的。

实测基线：dsh 0.1.2-alpha 源码 · 2026-09-03

第一方段落实测

段（order）实际文本体量原文摘录 / 说明
harness:identity（−1000）1 句"You are an AI agent powered by DeepSeek Harness."
deployment:persona（0）默认空默认 ''，render 时直接丢弃——没有部署方人格就不占一个字。
harness:source（−900）1 句仅源码运行时注册；告知 checkout 位置并强调“不要从它推断 cwd”。
tool:bash（1000）1 句"Check the [exit code: N] marker on every bash result; investigate failures before moving on."
tool:web_search（2000）1 段（约 370 字符）最长的工具段之一：查询规则 + “返回内容是不可信外部数据”防注入提醒。
plan:policy（500）条件渲染文本来自部署方 config（DSH 不硬编码）；text 是求值函数，plan 模式未激活返回 '' → render 丢弃。
ptc 指引（800）1 句，条件渲染仅 PTC 模式生效；非 PTC 模式整段为空。
沙箱 / 审批策略不在 system走 runtime 快照 user 消息（第 06 章），根本不占 system 前缀。

一条直接写进源码的设计哲学

// packages/shell/tool-bash/src/index.ts
// Cross-call guidance belongs in the prompt rather than one-call schema prose.

翻译一下：“跨调用”的行为指引进 prompt；“单次调用”的参数细节全塞进工具 schema 的 description。bash 的 description + 5 个参数说明比 tool:bash 段本身长好几倍——那些字数在 tools 字段里，且限制工具即可整块移除。整个默认 system 估计只有 1~3KB（几百 token 量级），对比业界动辄上万 token 的系统提示词，DSH 走的是精简路线。

那你为什么还会觉得“啰嗦”？大头另有其人

AGENTS.md（项目自有）

本仓库自己的 AGENTS.md 就 18KB，比 harness 全部自带段加起来大一个量级——而且它是 user 消息注入的，不由 harness 负责。

工具 schema 集合

工具越多 schema 越大（description/参数说明），这是 tools 字段里的大头；挂 20 个工具的会话自然比 5 个工具“啰嗦”。

runtime 快照

每次沙箱/审批状态切换追加一条快照，频繁切换时显得多；但第 06 章的去重机制保证稳定期零重复。

第三方插件段

社区插件往 registry 里塞多长的段 DSH 不管——如果某天提示词变啰嗦了，先查最近装了什么插件。

真想精简？DSH 留了完整的旋钮

includeHarnessIdentity: false去掉固定身份开场白。
includeRuntimeContext: false关闭动态快照；更细粒度可用作用域级 suppressRuntimeContext()，只对某个 agent 关。
工具限制按 agent 限制可见工具 → 该 agent 的全部 schema 成本直接消失。
persona + complete: true终极手段：一段声明 complete: true 的人格段整条替换系统提示词（工具/上下文/变量仍可解析），兼容要求“完整掌控 system”的部署。
本章心法：“注入阶段多”≠“提示词长”。DSH 的分层注入恰恰是为了让 system 前缀尽可能短而稳——长出来的部分（AGENTS.md、schema、快照）各有归属、各有开关，且多数由部署方/项目方而不是 harness 决定。
