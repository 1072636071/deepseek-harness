“运行还会注入”：动态上下文的去重快照机制

这一章回应你最直接的观察——为什么每个 step 的请求里都会冒出一段新的 “Current runtime context”。机制在 agent-loop 的 RuntimeContextProjection 里，简洁又关键。

本章对应源码：packages/core/agent-loop/src/runtime-context.ts
每 STEP 前

① assemble() 求值出“此刻快照”

装配结果里带着 contexts（本次求值的 sandbox/approval…）。agent 调用 project(快照文本, 组成它的各 context) 计算“要不要更新”。

比对 & 决定

② 与上一次保留的快照比对，变了才注入

RuntimeContextProjection 记住上一次真正发出并仍在 surface 上的快照。若本次文本与上次相同 → 不发；不同（策略切换、沙箱模式变化、首条快照）→ 生成新的 user 快照消息；若本次为空 → 发一句清除标记。

追加 & 串流

③ 新快照追加进历史，作为本 step 的上下文

快照落在直接 prompt 之后、工具结果之前。它的 source.form:'snapshot' 里还带 sections，方便追溯“这段是谁贡献的”。

核心代码只有四行逻辑

// packages/core/agent-loop/src/runtime-context.ts
project(current, sections) {
  if (this.retained === undefined && current.length === 0) return;
  const snapshot = current.length === 0 ? CLEARED : current;
  if (this.retained?.text === snapshot) return;  // 没变 → 不重复注入
  return createUserMessage({ content:[{type:'text',text:snapshot}],
    source:{ kind:'plugin', plugin: SOURCE, form:'snapshot', sections } });
}

三种情形，三种结果

情形上次快照状态本次求值结果投影动作
冷启动无上下文从未有过空文本什么都不发——retained===undefined && 空 直接返回。
稳定期有与上次相同不发——去重生效，零额外 token。
事实切换有不同文本发新快照（含“supersedes earlier”声明，模型自动以最新为准）。
事实清空有空文本发清除标记："Current runtime context: none. Earlier runtime-context snapshots no longer apply."
别把“每次都注入”理解成“每次都堆一坨”。同一状态稳定时，装配虽然每次都算，但投影会因文本相同而不产生新消息——真正触发注入的是策略/模式这类“事实级”切换。它特意把“当前值”放在历史尾部走，就是为了不动 system 前缀、保住 KV-Cache（第 07 章）。
