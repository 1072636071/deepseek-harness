# Agent Note：侧栏全局面板列表的上界

Status: implemented

[English](2026-10-21-sidebar-panel-group.md) | 中文

## 问题

`sidebar.panellist` 是任何插件都能注册的 root 作用域 list：ui-plugin-manager 以 order 0 注册，ui-schedule 为 10，第三方插件（MCP 连接器、Agent 中心等）继续往后追加。每一行都是 Workspace 浏览器上方的 36px 按钮，于是每多一个插件，会话列表就少一行，最终把整个浏览器挤出栏外。外壳既没有上界，也没有让用户收回这块空间的办法。

## 决策

外壳按 `order` 常显前 `PANEL_HEAD_ROWS`（四）行，其余行收进由外壳自己声明的披露分组。计数写在分组标题上（`更多面板（n）`／`收起更多面板`），因此折叠不会隐瞒某一行的存在。

### 为什么放在外壳而非面板注册表

把上限塞进 slot 注册表，会让所有 list 共用同一套策略，并让条目从 `entries()` 里消失，改变插件与测试观察到的事实。栏的纵向预算本来就归外壳所有，外壳也不认识任何具体面板 id，因此上界属于它的渲染过程：注册项保持完整，超集只是按预算决定渲染几行。

### 占位行还是卸载行

被隐藏的行卸载。每个 `PanelRow` 通过 `usePanelInfo` 订阅自己的选中态；把已折叠的行留在树上，会让这份订阅及其图标 slot 占用方在屏幕之外继续存活，却没有可见产物为它辩护。分组容器仍然渲染（空），因此标题的 `aria-controls` 始终可解析。

### 收起分组里的选中项

收起的分组若包含当前选中的面板，标题使用与选中行相同的选中底色。否则收起后的列表完全不显示选中态，而主列正在展示一个没有任何行承认的面板。展开后该选中态交回行本身，因此标题只在它是选中项唯一可见代表时才带选中态。

### 轨道宽度

56px 轨道放不下分组名称。那里每个已注册面板都按图标逐行渲染、标题不出现，因此收起侧栏后仍可一次点击到达任一面板。这处不对称来自栏宽，而不是第二套折叠策略。

### 持久化

展开状态由外壳声明的 store 持有（`stores.ts`，`dsh.sidebar.panels.v1`），而不是组件状态，因此它在外壳注册重建和页面刷新后都成立。持久值是单个布尔量、经 store 自带的持久化读写；过期或手工改写的条目也改变不了组件读取的形状。

## 备选方案

**在 slot 注册表里给注册列表设上限。** 否决：一套全局策略会套用到所有 list slot 上，而且把条目从 `entries()` 里隐藏会破坏统计注册项的观察方和断言其释放的测试。

**渲染全部行但让列表滚动。** 否决：列表位于 Workspace 浏览器上方的 flex 列中，剩余高度归浏览器所有。在栏内再嵌一个滚动区会让两块区域争夺滚动条，并让面板列表读起来像独立页面而不是导航。

**即使不到阈值也始终显示分组。** 否决：三行之下再加一个披露标题，等于为本来就放得下的内容多要一次点击和一行装饰；上界应该只在栏真的没空间时才出现。

**折叠成单个「更多」菜单而不是行内分组。** 否决：菜单把插件身份藏进弹层，也丢掉了 `sidebar.panellist` 约定存在的意义——逐行的图标；行内分组保留了每一行自己的标签与图标。

## 影响

- 插件作者不需要新 API：第五个及之后的注册项自动折叠，前四行保持其 `order`。
- `SidebarRootComponentProps` 增加 `PropsStore<PanelListStoreHandle>` 这份 share。所有直接渲染 `SidebarRoot` 的地方（含测试）都必须提供 `useStore` 与 `actions`；生产中由渲染器从已声明的 store 绑定。
- 四行是布局常量，不是用户设置。它对应在最小侧栏宽度下仍让 Workspace 浏览器可用的高度预算；改动它是外壳的布局决策。
