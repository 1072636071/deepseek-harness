# Agent Note: 上下文占用面板 —— 悬停预览、点击固定

Status: implemented

[English](2026-09-23-context-meter-hover-preview.md) | 中文

## 问题

输入框旁的上下文占用圈圈原本只能点击后才展开占用明细面板（[原始决策](../../archived/feature/2026-08-05-composer-context-meter-breakdown.md)）；悬停只显示一个带百分比读数的提示气泡。要看构成——面板真正的内容——必须刻意点一下，而面板展开后又像菜单一样会被一次误点外部关掉：用户只是想顺手看一眼，却要付出两次交互，外加一个根本没想要的固定态。

## 决定

`ContextMeter`（packages/client/ui-conversation/src/client/skeleton/ContextMeter.tsx）把原来的单一 `open` 标志拆成 `hovered` 与 `pinned`，任一为真即渲染面板：

- **悬停即刻预览。** 指针进入圈圈或面板（二者都在根 span 内）即无延迟展开；离开即收起，除非已固定。`.panel::after` 是覆盖面板下方 8px 缝隙的隐形悬停桥，指针从圈圈移向面板时永远不会离开根元素的热区。
- **点击固定；再次点击解除。** 圈圈按钮只切换 `pinned`；未固定前面板可见性始终跟随 `hovered`，解除固定时若指针已离开，面板立即收起。
- **消失逻辑只作用于固定态。** 点击外部与 Escape 只清除 `pinned`；悬停预览无需消失逻辑，因为指针离开本身就会收起。容量在挂载期间消失时同时解除固定与悬停态——已卸载的圈圈收不到 `mouseleave`，容量恢复后不得显示指针早已离开的面板。
- **提示气泡让位于面板。** 面板可见期间 `Tooltip` 禁用，悬停路径展示的是占用明细而非重复的百分比气泡；键盘聚焦仍通过气泡朗读读数，`aria-expanded` 跟随的是可见性而非固定态。

## 备选方案

- **维持原样的仅点击展开。** 因可达性被否：占用读数是扫一眼即得的环境信息，把明细藏在一次点击加菜单式消失之后，让最常见的"看一眼"场景成为成本最高的路径。
- **悬停显示零延迟气泡而非面板。** 被否：气泡只复述百分比，用户要看的构成在面板里，同一次悬停叠两层展示面会互相打架。
- **悬停意图延迟（约 150 ms）。** 对该控件被否：面板挂载开销低，误悬停离开即自收，且圈圈位于角落，指针只会朝输入框 chrome 掠过，不会横穿用户的阅读内容。
- **在面板内放固定开关。** 被否：面板没有任何可交互元素，展开的入口本就归圈圈，第二个开关会把一个决定拆到两个面上。

## 后果

- 指针停在圈圈上时面板持续挂载；流式更新 `contextPressure`/`contextBreakdown` 投影会实时重渲染面板——此前只在固定态下可见。
- 组件用例钉住了悬停展开、固定后指针离开仍显示、解除后再悬停重新预览的序列；原有的点击、消失与容量消失用例现在经由固定态断言同样的结果。
- 生成的 slot 目录与本地化词典均无变化，没有产品文案迁移。
