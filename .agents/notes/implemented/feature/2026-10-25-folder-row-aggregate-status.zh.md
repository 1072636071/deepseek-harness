# Agent Note: 文件夹行聚合状态

Status: implemented

[English](2026-10-25-folder-row-aggregate-status.md) | 中文

## 问题

按文件夹分组把文件夹行渲染为标题、展开三角与菜单，而承担聚合状态点的成员工作区行只在文件夹展开时才渲染，该状态点来自[工作区行聚合状态](2026-10-04-workspace-row-aggregate-status.zh.md)。因此折叠的文件夹无法提示其中某个工作区需要人工处理、仍在运行，或已完成未查看——正是那份笔记为折叠工作区补上的缺口，只是上移了一层。

## 决策

每个文件夹行都在展开三角之后的同一行位置携带与工作区行相同的聚合状态点。文件夹不拥有 Session，因此 `folderRowStatus` 按该决策固定的优先级——需处理、运行中、未查看、有会话、无会话——折叠其成员工作区行的状态；没有成员、或成员全部为无会话的文件夹报告 `inactive`。

| 状态 | 状态点 | 含义 |
|---|---|---|
| `attention` | 红色 `error` | 某个成员工作区报告需处理 |
| `running` | `ongoing` 加载点 | 某个成员工作区正在运行 |
| `unread` | 绿色 `done` | 某个成员工作区在主视图之外完成，尚未查看 |
| `present` | 蓝色 `info` | 该文件夹至少有一个非无会话的成员 |
| `inactive` | 灰色 `idle` | 该文件夹没有成员，或每个成员都是无会话 |

文件夹布局本就持有全部成员工作区行，无论展开与否，因此这次折叠与文件夹的展开状态无关，且无需改动文件夹数据：`layoutFolderSections` 按归属对工作区分组，从不按 `expanded` 过滤；浏览器侧的行构建对这些成员的 `status` 调用 `folderRowStatus`。没有任何成员 Session 被读取第二遍，`FolderHeaderNode` 保持其文件夹事实，不新增状态字段。

文件夹行去掉了 `aria-label={folder.title}`。行级标签会遮蔽状态点自身的 `role="img"` 名称，导致读屏只念出文件夹标题、永远不念聚合状态。该行现在与工作区行一样由自身内容命名：标题文本加上状态点来自 `status.workspace.*` 字典条目的无障碍名称。这些条目本就未包含"工作区"字样，因此文件夹行直接复用，不另建一套文案。

## 考虑过的替代方案

**在文件夹层直接折叠成员 Session，而不是折叠成员行。** `workspaceRowStatus` 已折叠单个工作区的未归档 Session；再独立折叠文件夹的 Session 会复制该优先级、复制需处理判别值规则，并重复读取成员行已经汇总过的每个 Session。

**在 `deriveGroups` 中把状态放到 `FolderHeaderNode` 上。** `deriveGroups` 只从 Session 列表派生工作区分组，对文件夹一无所知；文件夹归属由 `layoutFolderSections` 之后在浏览器侧连接。把文件夹字段加在那里，要么把文件夹归属搬进树派生，要么留下一个树内没有生产者的字段。

**保留 `aria-label` 并把状态拼进去。** 这会让文件夹的无障碍名称变成"Work：某个会话正在运行"，在本地化字典之外自造拼接字符串；工作区行现有的内容派生名称才是应当对齐的模式。

**为文件夹单独建文案 key。** 现有的 `status.workspace.*` 文案没有出现"工作区"字样，在文件夹行上读起来同样正确，另建一套只会多出一份需要同步维护的翻译面。

## 结果

折叠的文件夹现在无需展开、也无需读取任何成员 Session，就能报告其中是否有需要人工处理、仍在运行、或已完成未读的内容。文件夹行的无障碍名称从纯标题变为标题加状态文案——与工作区行此前的读法相同——文件夹行测试、文件夹浏览器测试与行测试都已随之更新。

该状态点报告的是成员行的聚合状态，而非独立的文件夹事实：待处理交互仍不会聚合到任一种行上，因此相关限制继续有效。只含无会话成员的文件夹读作无会话，而不是空文件夹的措辞，因为在该行的词汇里两者是同一状态。

`folderRowStatus` 钉住优先级、空与全无会话情形，以及成员顺序无关性；文件夹浏览器测试在真实渲染路径上钉住五个状态点、折叠文件夹的状态点，以及混合文件夹取最紧急成员。i18n 门禁、Agent Note 格式门禁、翻译配对门禁与文档门禁全部通过。
