# Agent Note: 工具描述长度门禁

Status: implemented

[English](2026-08-27-tool-description-length-gate.md) | 中文

## Problem

前两批描述精简已将全部模型可见工具描述缩短（63 个工具，渲染描述总量 21,627 -> 17,489 字符，-19.1%），但没有任何机制强制这一预算：未来任何改动都可能让某条描述静默回涨到论文式长度，精简激励只存在于评审纪律中。极简原生插件工作（win-shell-mcp 批次 19）还依赖"全量目录提示词有界"这一前提；无界回涨直接破坏该前提，而 ADR-0016 已将 token 成本定为交互设计第一优先级。

## Decision

`verify-tool-catalog` 现在同时门禁每条描述的长度。生成器在收成每个包的 schema 后立即断言每条模型可见描述都在其字符预算内：默认上界 200 字符；包键注册表（`scripts/gen-tool-catalog.ts` 的 `DESCRIPTION_LENGTH_LIMITS`）持有显式的逐工具上限，注释逐一说明放宽理由与观察到的不可约行为事实对应（一次性 `bash` 850、`pwsh` 1100、`workflow` 2000、`todo_write` 750、`cordis_*` 审批/版本指针保证、`glob` 400 等封顶/采样披露等）。断言挂在 `collectToolCatalog()` 内部，因此生成与 `--check` 双路径都失败关闭；收成条目传播 manifest 的 `dir`，跨包同名工具因此保持单一命名空间的限额键。负例测试覆盖恰好压线的通过、违规消息（`tool len>limit`）、上限查找顺序，以及证明全部存量描述都在预算内的全树扫描。

两批精简后的重测：63 个工具共 17,489 描述字符（均值约 278）。逐条通读全部 63 条描述——不止 29 条超默认预算者——确认均为稠密行为事实（钩子签名、拒绝标记、投递语义），没有可继续裁剪的说教句或示例堆砌；注册表如实记录现状而非假装更低的界限。围绕本次精简重新验证了极简 preset 锚定表面：重放仍然钉住固定单行 persona、恰两个 shell+编辑器工具、持久状态语义与带行号的编辑器输出；apps/web 车道在 win32 宿主上确定性红，因为 preset 按 platform 门控 bash/pwsh 栈（经 stash 对照证实与本批改动前后完全一致；Linux CI 重放为绿）。

## Alternatives considered

**仅依赖评审。** 否决：新鲜度已经对过期目录失败关闭，放任最新的回归轴开放会让精简成果离"一次重构就蒸发"只差一步。

**立即全域强制 200。** 否决：这会迫使本批就砍掉不可约事实——sandbox 拒绝标记、审批流、钩子失败语义——用模型正确性换一个更好看的数字，违背工单自身的验收措辞（"行为事实可放宽"）。

## Consequences

超出预算的描述改动会让 `pnpm run gen-tool-catalog` / `verify-tool-catalog` 以可操作的报错失败：裁到行为事实，或登记一个有依据的上限——每次放宽都成为可见的已评审决策而非漂移。上限是天花板不是目标：新工具应以 200 字符默认值为准。结合工单 02 对 API-SDK 提示段的裁剪，本批整体将渲染目录描述成本从 21,627 降至 17,489 字符，且 wire schema 除 description 字段外字节不变。
