# PRD：会话模型选择——配置入口 + 模型可见性 + 两列布局

**Status:** ready-for-agent

## 问题陈述

用户在会话中切换模型时遇到三个断点：

1. 想改模型配置（厂商/模型/可见性）时，会话选模型的下拉里没有直达入口，必须绕道设置页层层找。
2. 模型列表把厂商和模型混在一列里，厂商多、模型多时难以定位到目标模型。
3. 想要在某些会话/场景中隐藏部分模型（例如把不常用或实验中的模型收起），当前无任何"模型可见性"手段，所有已配置模型一律出现。

根因：会话选模型 UI（`ui-model-selection`）与模型配置 UI（`ui-settings-models`）彼此孤立、无跳转；模型数据模型（`ModelCatalogModel`）无可见性字段；选模型列表是单列分组结构。

## 解决方案

为会话选模型下拉补齐一条"模型配置"直达链路，并在同一页面内提供两段式（厂商/模型）浏览；在设置页为厂商卡片补模型级的可见性开关，让用户能逐模型隐藏不需要的模型，隐藏的模型不再出现在会话选模型处。

三个改动点：

1. **配置入口**：会话选模型下拉的根菜单（模型/推理等级两行）处新增「模型配置」入口，点击导航到设置页的「模型」分段。
2. **模型可见性**：设置页「模型」分段的每个厂商卡片内提供模型可见性开关；会话选模型渲染时过滤掉被隐藏的模型。
3. **两列布局**：会话选模型下拉的模型选择改为两列右幕式——左列厂商，右列当前选中厂商的模型。

## 用户故事

1. 作为会话用户，我想要在当前会话选模型的下拉里直接进入模型配置，以便我不必关闭会话、绕到设置页才能改模型。
2. 作为会话用户，我想要看到"模型配置"入口，以便我知道在这个下拉里就能管理模型，从而减少切换心智成本。
3. 作为会话用户，我想要在阅读模型列表时先看到厂商、再选该厂商下的模型，以便厂商一多时我能顺着厂商快速定位模型。
4. 作为会话用户，我想要左列点击某个厂商后，右列立即显示该厂商的模型，以便我不必在一整页分组里上下滚动找模型。
5. 作为会话用户，我想要两列各自可滚动、且布局稳定，以便模型/厂商数量很多时仍能逐个查看而不挤成一团。
6. 作为模型配置者，我想要在「设置→模型」的某个厂商卡片里，为该厂商的每个模型设置可见/隐藏，以便把当前不用的模型从会话选择里收起来。
7. 作为模型配置者，我想要可见性开关默认对大数为可见，以便我不做任何设置时所有模型照常可选（不破坏现有体验）。
8. 作为会话用户，我想要隐藏的模型不再出现在会话选模型列表里，以便我不会误选一个已被自己收起的模型。
9. 作为会话用户，我想要"当前已选中的模型"即使被隐藏，其已选状态仍保持，以便收起某模型不会让正在使用的会话丢模型。
10. 作为配置者，我想要在设置页把某个模型重新设为可见后，会话选模型列表立即恢复该模型，以便调整设置后无需刷新即生效。
11. 作为配置者，我想要可见性设置持久化，以便重启/换端后我的隐藏选择依然保留。
12. 作为会话用户，我想要两列布局中的键盘操作（方向键在厂商/模型间移动、回车选中）仍然可用，以便无障碍使用。
13. 作为会话用户，我想要在下拉里"模型配置"入口导航到设置页的「模型」分段时定位准确，以便我落地就是模型配置页而不是设置首页。

## 实现决策

- **改动包**：`ui-model-selection`（会话选模型下拉）与 `ui-settings-models`（设置页模型分段）。

- **可见性语义**：每个模型一个布尔 `visible`（缺省视为可见）。不引入三态（无常用/默认）。

- **可见性数据 seam（A）**：可见性作为 provider profile 的模型字段，随厂商 `models` 数组读写，复用现有 `settings.mutate`/`describe` 通道与 `ModelListEditor`。**内置 catalog 模型（厂商未自定义 models 数组）不作可见性配置，视为始终可见**——覆盖范围即"配置了模型列表的厂商"。

- **过滤 seam**：client 侧过滤。会话选模型渲染时按可见性裁剪 hidden 模型；不修改 Host `buildModelCatalog`。需新增 client 读取该 profile 可见性的通道（Data-access ladder 上尽量复用 settings describe / 注入回调），Host 保留完整 catalog 以便路由判断与诊断。

- **两列交互（D4）**：左列厂商，右列联动显示当前选中厂商的模型（右幕式）。需要"当前选中厂商"的本地状态并在右列重渲染。

- **配置入口（D5b）**：下拉根菜单新增「模型配置」行；导航通过新增注入回调实现（`ui-settings`/设置入口 provide，`ui-model-selection` consume），`ui-workspace` 现无设置路由跳转，须新增。

- **i18n**：所有新文案走 `ui-model-selection` 与 `ui-settings-models` 的 `locales.ts` 类型化字典（zh/en 对齐，`ModelKey` 字面量枚举为事实源）。

- **样式**：CSS Modules，复用 `--dsw-*` 语义 token；不新增组件库依赖。

- 约束：不触碰会话持久化 `SESSION_FORMAT_VERSION`、不新增模型可见的会话事件（过滤是纯展示决策，非模型可见输入）。

- 破坏面：bundle 需重打（`pnpm --filter <pkg> bundle`）后 `dsh web` 才生效。

## 测试决策

- 只测外部行为，不测实现细节（是否内部某函数被调、行数、class 名）。

- **`ui-model-selection`**：组件 spec（jsdom）feed store/snapshot 数据——

  - 两列：左列行数=厂商数；右列=当前选中厂商模型数；切换左列选中，右列随动。

  - 可见性过滤：feed 含 hidden 模型快照，断言该模型不在右列；当前已选 hidden 模型仍展示且保序。

  - 配置按钮：点击触发注入的导航回调；无回调注册时不渲染或静默。

  - 无障碍：方向键在厂商/模型间移动、回车选中保持可用。

  - 先例：`ui-model-selection/tests/model-select.client.spec.tsx`（已有组件 spec），沿用其 fixture/store feed 方式。

- **`ui-settings-models`**：模型可见性 checkbox——

  - 写：勾选/取消触发 settings mutate，payload 正确携带该模型 `visible`。

  - 读回：describe 返回后 checkbox 反映持久化值。

  - 先例：`ui-settings-models/tests/*` 现有 store/editor 组件 spec。

- **跨端一致性**：新增可见性过滤 + 设置写入对拍（设置页 mark hidden → 会话下拉该模型消失）。

- **门禁**：`pnpm run test:gui`；涉及可见 UI 输出变更时补 `DSH_SNAPSHOT=replay pnpm run test:web`；本变更产生新版文案时校验 `verify-client-ui-i18n`。

## 超出范围

- 三态可见性（favorite / default / hidden）。

- 内置 catalog 模型（未自定义 models 数组的厂商）的逐模型可见性配置。

- Host `buildModelCatalog` 过滤（刻意不碰）——保持 Host 完整 catalog 供路由判断与诊断。

- 会话级/单会话内叠加的可见性覆盖（本次为全局模型可见性）。

- 重新设计 ModelSelect 根菜单结构（保留模型/推理等级 + 新增配置行）。

- 切换后模型可见性在会话记录 / 转录中的记载（无模型可见会话事件）。

## 补充说明

- 与 memorial `001-model-config-visibility`（`docs/memorial/001-model-config-visibility/`，含 ADR `adr-001`）对齐；该 memorial 为唯一决策来源。

- 可见性过滤是**纯展示**决策：隐藏不改变模型可用性与路由能力，Host 仍能回显/诊断隐藏模型。

- 先保持"最小改动"：两列只重构 `ModelSelect` 的 `pane === 'model'` 渲染块，不重排其余生命周期/无障碍逻辑。

- 若内置 catalog 厂商的模型也需要可见性，属后续扩展（超出范围 2 条），应另立 issue，不影响本 PRD 落地。
