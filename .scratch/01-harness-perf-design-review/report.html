总评

一句话结论先行。

工程质量显著高于平均水平 性能仍有明确余量

这是一份纪律性极强的代码库：安全（0600 权限校验、防 symlink planting、防 ripgrep 配置注入）、取消语义（AbortSignal 全链路传播）、资源有界性（输出 tail 封顶 + spill、write-behind 批写）三方面的完成度是多数工业级项目达不到的。

性能余量呈单一系统性主题：热路径上的重复深拷贝与重复重建。约 60% 的性能发现都归于"同一个值在一次请求/一个 delta/一次工具调用内被克隆或重建 2–4 遍"——工具注册表 view() 每次调用重建、流式 delta 被 3 次深拷贝、工具结果被 snapshot 3–4 遍、系统提示每步 structuredClone 全部 schema、token-meter 全量重定价。修复方向明确且局部化（registry generation 记忆化、ownership-transfer 代替克隆、增量 fold），不需要动架构。

设计优雅度总体是深模块风格（Ousterhout 意义上）——PersistenceBackend、output-retention、compaction 事务、SubagentContinuationManager 都是教科书级。主要债务集中在四处：core/tools/index.ts 1945 行 God 文件、一次工具执行的状态散落 5 张 WeakMap、三个 out-of-process subagent provider 平行重复同一生命周期骨架、HTTP 错误→稳定码映射在两个 LLM 适配器重复且已开始漂移。

五个最值得修的发现

按「影响面 × 修复收益」排序，全部有代码证据。

1

工具注册表 view() 每次调用重建全量索引

一次工具调用触发 view() 5 次以上，每次沿 scope 链重建 Map/Set 并逐层 admits() 过滤，O(层数×工具数) 分配。ScopedLayers.onChange 已有变更通知，按 registry generation 缓存即可消除。

packages/core/tools/src/index.ts:1151,1203,1379,1545

2

流式 delta 每个 token 被深拷贝 3 次

append 时 snapshotJsonValue + deepFreeze，分发后 persistence 又 structuredClone，落盘 coordinator 再全批快照一次。事件在 append 处已冻结，persistence 可直接共享引用；chunk 类事件可轻量校验。

core/session/src/index.ts:612,625 · session-persistence/write-behind.ts:47 · coordinator.ts:698

3

PTY scrollback 每个 chunk 做 O(4MB) 全量扫描

BoundedTextBuffer.append 每次 chunk 对整个缓冲 split('\n')，utf8Tail 用 Array.from 全量拆码点。构建类命令高速输出时 CPU 被输出泵吃满——全库唯一真正的 O(n²)。改环形缓冲 + 尾部字节回退找 UTF-8 边界。

packages/terminal/terminal-bash/src/session.ts:31-67

4

单次工具结果被深拷贝 3–4 遍

createSuccessResult 对结果连续 snapshot 三次，finishScheduledExecution 又两次。canonicalResults 已能识别"已归一"结果，finish 阶段对 canonical 结果直接短路即可。大输出工具（read/bash）每条结果都在付这笔税。

packages/core/tools/src/index.ts:1792-1822,1630-1645

5

聊天长列表无虚拟化，回翻只增不减

ChatView 对 order.map 全量渲染；分页只控制拉取不控制保留，loadOlder 不断 prepend 且永不裁剪。长会话重度回翻后，每次 append 的 reconcile 和内存线性上涨。

packages/client/ui-chat/src/client/chat/ChatView.tsx:595-614 · session-controller/.../session.ts:413-434

系统性主题：五个关键发现里三个是"重复克隆/重建"。这个代码库已经用 deep-freeze + 事件溯源解决了大部分状态一致性问题，但冻结前的防御性拷贝被叠加使用——deep-freeze 本身就是所有权契约，冻结后共享引用是安全的。把"snapshot + freeze"成对出现的调用点改为"冻结即转移所有权"，可以一次性消掉最大一类开销。
